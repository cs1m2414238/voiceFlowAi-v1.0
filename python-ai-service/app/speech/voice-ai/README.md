# Voice AI Module

## Overview & Responsibilities
This is the standalone **Voice AI Engineering Module** extracted from the VoiceFlow AI platform. It provides high-performance, asynchronous Speech-to-Text (STT) transcription, multi-provider Text-to-Speech (TTS) audio synthesis, and an end-to-end Voice AI Integration Pipeline for real-time speech interactions.

### Primary Responsibilities:
1. **Speech-to-Text (STT)**: Captures user microphone audio, processes it through Faster-Whisper, and returns clean recognized text.
2. **Text-to-Speech (TTS)**: Synthesizes text generated by AI/application into spoken studio-quality neural audio via Microsoft Edge-TTS, ElevenLabs API, or gTTS fallback.
3. **Voice AI Pipeline Integration**: Provides clean connection points (`process_voice_pipeline`) and FastAPI endpoints to link STT and TTS seamlessly with any AI/LLM backend or web client.

---

## Architecture Flow

```
User Voice Audio (Mic / File)
          ↓
Speech-to-Text (STT Service / Faster-Whisper)
          ↓
Recognized Text Transcript
          ↓
AI Application / LLM Handler Callback
          ↓
Response Text Output
          ↓
Text-to-Speech (TTS Service / Edge-TTS / ElevenLabs / gTTS)
          ↓
Synthesized Audio (.mp3 / .wav)
          ↓
Audio Stream Playback → User
```

## Technologies Used

* **Language**: Python 3.10+, TypeScript (Frontend capture hook)
* **STT Framework**: `faster-whisper` (Whisper C++ binding with CPU int8 quantization)
* **TTS Frameworks**: `edge-tts` (Microsoft Neural Voices), ElevenLabs API, `gTTS` (Google TTS)
* **Audio Processing**: Standard Python `wave`, `struct`, `math` (Synthetic 16-bit PCM fallback)
* **Web Framework**: FastAPI, `python-multipart`, `FileResponse`
* **Frontend Audio Capture**: HTML5 `navigator.mediaDevices.getUserMedia` & `MediaRecorder` API

## Environment Variables

Copy `.env.example` to `.env` and adjust settings:
```bash
cp .env.example .env
```

Key variables:
* `STT_PROVIDER`: `"faster-whisper"` (default) or `"mock"`.
* `TTS_PROVIDER`: `"edge-tts"` (default), `"elevenlabs"`, or `"gtts"`.
* `ELEVENLABS_API_KEY`: `"your_elevenlabs_api_key_here"` (Required only if `TTS_PROVIDER="elevenlabs"`).
* `AUDIO_DIR`: Directory path for storing input/output audio files (default: `./audio_storage`).

## Usage Guide

### 1. Standalone Speech-to-Text (STT)
```python
from stt.speechToText import stt_service

# Transcribe local audio file
transcript = stt_service.transcribe_audio("sample_user_voice.wav")
print("Recognized Text:", transcript)
```

### 2. Standalone Text-to-Speech (TTS)
```python
from tts.textToSpeech import tts_service

# Synthesize text into speech audio file
output_file = tts_service.synthesize_speech(
    text="Hello! How can I assist you today?",
    output_path="./audio_storage/greeting.mp3",
    agent_type="manager"  # Persona voice mapping
)
print("Audio generated at:", output_file)
```

### 3. Integrated Voice Pipeline
```python
from integration.voicePipeline import process_voice_pipeline

# Define your AI/LLM handler function
def mock_ai_handler(user_text: str) -> str:
    return f"AI received: {user_text}. Here is the answer."

# Run complete Voice Pipeline (Audio -> STT -> AI -> TTS -> Audio)
result = process_voice_pipeline(
    audio_file_path="input_mic.wav",
    ai_handler=mock_ai_handler,
    agent_type="support"
)

print("User said:", result["user_transcript"])
print("AI responded:", result["agent_response"])
print("Generated Audio File:", result["output_audio_path"])
```

app.include_router(voice_router)

## Error Handling & Resiliency

1. **File Missing**: Raises standard `FileNotFoundError` if input audio path does not exist.
2. **STT Model Failure**: Catches Faster-Whisper errors gracefully and falls back to resilient dev transcript.
3. **TTS Multi-Layer Fallback**:
   * Layer 1: ElevenLabs API (if configured & key valid).
   * Layer 2: Microsoft Edge Neural TTS (`edge-tts`).
   * Layer 3: Google Text-to-Speech (`gTTS`).
   * Layer 4: Native 16-bit PCM synthetic WAV chime generator (zero network dependency).
4. **Browser Audio Fallback**: Client-side hook falls back to Web Speech API `window.speechSynthesis` if HTML5 audio element fails.
